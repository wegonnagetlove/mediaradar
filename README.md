# Newsroom Radar

Новостной радар для Telegram‑каналов. Бесплатно на GitHub Actions: собирает свежие публикации из Instagram, телеграм‑каналов, RSS и Google News, сверяет с конкурентами, отбирает лучшее и присылает в ваш Telegram готовые посты в стиле канала.

> Instagram и Threads принадлежат Meta, признанной экстремистской и запрещённой в РФ. Публичные аккаунты используются только как новостные источники.

## Расписание

| Время (МСК) | Что приходит |
|---|---|
| 06:55 | **Утренний выпуск**: «Доброе утро!» и до 20 новостей за ночь. Каждая новость одна строка: короткий заголовок, который сам является ссылкой на первоисточник. Сначала Россия, потом мир. Если ночью ничего не было, приходит одна строка. |
| 07:15–23:45, каждые 15 минут | Новости по мере поступления, готовыми постами в стиле канала, каждый отдельным сообщением. |
| 00:00–06:55 | Тишина. Всё, что выйдет ночью, попадёт в утренний выпуск. |

Выпуск стартует в 06:55, потому что GitHub ставит запуски в очередь и обычно опаздывает на несколько минут: так список приходит около 07:00. Время меняется в `.github/workflows/radar.yml` (в UTC, Москва = UTC+3). Утренний выпуск можно вызвать вручную: Run workflow → mode `D`.

## Как это работает

```
 Instagram (Graph API / Apify / RSS)  ┐
 Телеграм‑каналы (t.me/s, точное время)│
 RSS изданий (WWD, Variety, Dezeen…)   ├─► окно 60 мин ─► память: только новое ─► нейросеть: отбор
 Google News (BoF, The Cut, Puck, РФ)  │                                             │
 Threads и X (поиск нейросетью)        ┘                                             ▼
                                      конкуренты t.me/s/… + медиа РФ ─────► сверка «уже есть у…»
                                                                                     │
                                       первоисточник: точное время и текст ◄─────────┘
                                                                                     │
                                       нейросеть: пост в стиле канала ─► Telegram‑бот вам в личку
```

Время публикации берётся у самого источника: из API Instagram, из атрибута поста в Telegram, со страницы статьи (`article:published_time`, JSON‑LD). Если страница дала время старше окна, новость отбрасывается. В заголовке каждой новости указано, откуда взято время.

Каждая новость приходит **отдельным сообщением**: его можно сразу переслать или скопировать в канал. Первое сообщение выпуска — сводка: «⚡️ 2 новости: Заголовок; Заголовок».

## Запуск за 15 минут

**1. Репозиторий.** Создайте на GitHub репозиторий и загрузите в него эти файлы (или нажмите Fork). Публичный репозиторий даёт Actions без лимита минут; в приватном бесплатно 2000 минут в месяц, тогда поменяйте расписание на `*/30 * * * *` в `.github/workflows/radar.yml`. Ключи в коде не хранятся, поэтому публичный репозиторий безопасен.

**2. Telegram‑бот.** Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, получите токен. Напишите своему боту любое сообщение, откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и возьмите число из `"chat":{"id":…}`. Если результаты должны приходить в закрытый канал редакции, добавьте бота туда администратором, а chat_id канала начинается с `-100`.

**3. Ключ нейросети.** Любой из провайдеров в таблице ниже. По умолчанию Claude (`provider: anthropic`).

**4. Secrets.** Settings → Secrets and variables → Actions → New repository secret:

| Secret | Что это | Обязателен |
|---|---|---|
| `LLM_API_KEY` | ключ выбранной нейросети | да |
| `TELEGRAM_BOT_TOKEN` | токен от BotFather | да |
| `TELEGRAM_CHAT_ID` | куда присылать | да |
| `IG_ACCESS_TOKEN`, `IG_USER_ID` | Instagram через официальный API | для Instagram |
| `APIFY_TOKEN` | Instagram через Apify | вместо двух предыдущих |

**5. Проверка.** Actions → «Радар новостей» → Run workflow → action: `check`. В отчёте запуска видно, сколько публикаций отдаёт каждый источник и каждый аккаунт Instagram. Затем Run workflow → mode `A`, action `run`: придут первые новости. Дальше радар работает сам.

## Instagram

Три способа, выбирается в `config.yaml → instagram.provider`. Аккаунты перечисляются там же, российские помечаются `region: ru`, чтобы шли в приоритет.

### graph: официальный API, бесплатно (рекомендуется)

Метод Business Discovery Instagram Graph API отдаёт последние посты любого **бизнес‑ или авторского** аккаунта с подписью, ссылкой и точным временем. Большинство изданий, брендов, критиков и артистов используют именно такие аккаунты.

1. Заведите профессиональный аккаунт Instagram (бизнес или автор; можно пустой, служебный) и привяжите его к странице Facebook (в настройках страницы или в Meta Business Suite).
2. На [developers.facebook.com](https://developers.facebook.com/) создайте приложение типа Business и подключите продукт Instagram (API с входом через Facebook). Публиковать приложение и проходить проверку не нужно: для собственного аккаунта хватает режима разработки.
3. В Graph API Explorer выберите приложение и выдайте токен с разрешениями `instagram_basic`, `pages_show_list`, `pages_read_engagement` (если страница в бизнес‑портфеле, ещё `business_management`).
4. Узнайте `IG_USER_ID`: запрос `me/accounts?fields=instagram_business_account` вернёт id вашего Instagram.
5. Токен из Explorer живёт час. Выпустите долгосрочный: либо обменом на 60‑дневный (раз в два месяца нужно обновлять), либо, надёжнее, токен **системного пользователя** в Meta Business Suite, он не истекает.
6. Проверьте в Explorer: `<IG_USER_ID>?fields=business_discovery.username(bof){media.limit(1){timestamp,permalink}}`. Пришёл пост — кладите `IG_ACCESS_TOKEN` и `IG_USER_ID` в Secrets.

Ограничения метода: личные (не профессиональные) и закрытые профили не видны, аккаунты с возрастным ограничением не видны, сторис недоступны. Лимит Meta около 200 запросов в час на токен: 12 аккаунтов каждые 15 минут дают 48 запросов, запас большой. До 40 аккаунтов на частоте 15 минут укладываются спокойно.

### apify: платный парсер публичных постов

Видит и личные публичные профили. Зарегистрируйтесь на [apify.com](https://apify.com), возьмите API‑токен в `APIFY_TOKEN`, поставьте `provider: apify`. Оплата идёт за каждый полученный пост, поэтому задайте `min_interval_minutes: 30` или `60`: Instagram будет опрашиваться реже остальных источников. Если входные поля актора поменяются, их можно передать через `apify_input`.

### feed: любой RSS‑мост

У отдельного аккаунта можно указать `feed: <url>` (например, свой экземпляр RSSHub). Такой аккаунт читается по RSS при любом `provider`; удобно для пары личных профилей, которых не видит `graph`.

### Threads и X

Бесплатного API для чтения чужих постов у них нет. При `social_search: true` нейросеть с веб‑поиском раз в запуск ищет свежие публикации аккаунтов из `social_accounts`. Время у таких находок помечается как «время по: поиск» или «пересказ», проверяйте его перед публикацией.

## Нейросеть

Меняется двумя строками в `config.yaml` и ключом `LLM_API_KEY`.

| provider | Пример model | Веб‑поиск (Threads, X, режим agent) |
|---|---|---|
| `anthropic` | `claude-sonnet-5-5`, `claude-opus-5-5` | да |
| `openai` | модель ChatGPT с доступом к API | да |
| `openrouter` | любая модель каталога OpenRouter | да (суффикс `:online`) |
| `gemini` | модель Gemini | нет |
| `deepseek` | `deepseek-chat` | нет |
| `custom` | любой OpenAI‑совместимый API, задайте `base_url` | нет |

Для качества текста лучше старшая модель; отбор и пост делаются двумя вызовами за запуск, и только когда есть свежие кандидаты.

Режим `engine: agent` отключает сбор кодом: нейросеть сама ищет в вебе по полному редакционному промпту `prompts/editor.md`, как в чате. Медленнее и дороже, время публикаций проверяется слабее; полезен как запасной вариант.

## Что настраивается в `config.yaml`

**Окно и объём:** `modes` (60 минут, до 3 новостей по расписанию, 3–5 при ручном запуске).
**Конкуренты:** `competitors_telegram` (их ленты t.me/s сверяются при каждом отборе) и `competitors_media`.
**Источники:** `sources.telegram` (каналы‑первоисточники; сюда стоит добавить инсайдерские каналы шоу‑бизнеса, моды и музеев), `sources.rss`, `sources.google_news` (запросы на русском и английском, окно подставляется само).
**Уведомления:** `notify.silent_night` (без звука с 01:00 до 08:00 МСК), `notify.send_empty`.
**Строгость времени:** `strict_time: true` отбрасывает статьи, у которых время не подтвердилось на самой странице.
**Стоп‑темы:** `stop_topics`.

Тексты для нейросети лежат в `prompts/`: `triage.md` (отбор), `writer.md` (стиль поста), `social.md` (поиск по соцсетям), `editor.md` (полный промпт для режима agent и для чатов).

## Память и повторы

`state/seen.json` хранит всё, что радар уже видел за три дня, и заголовки отправленного за двое суток. Повторно сюжет не придёт, даже если его подхватит другой источник: отправленное передаётся на отбор как «уже есть у нас». Память переживает запуски через кэш GitHub Actions. Сбросить: `python -m radar reset` локально или удалить кэш в Actions → Caches.

Если нейросеть три запуска подряд отвечает ошибкой (кончились деньги на ключе, неверный ключ), бот один раз пришлёт предупреждение.

## Локально

```bash
pip install -r requirements.txt
export LLM_API_KEY=… TELEGRAM_BOT_TOKEN=… TELEGRAM_CHAT_ID=…
python -m radar check                 # здоровье источников
python -m radar run --no-llm          # только свежие кандидаты, без нейросети
python -m radar run --mode A --dry-run
python -m radar run --mode A
python -m pytest -q
```

## Честные ограничения

1. GitHub запускает расписание с задержкой, обычно до 5–15 минут, в часы пик бывает больше. Минимальный шаг расписания 5 минут; чаще 15 минут ставить смысла мало.
2. Google News индексирует статьи с задержкой от минут до часа. Для скорости важнее прямые RSS и телеграм‑каналы.
3. Instagram: сторис и закрытые профили не доступны ни одним законным способом.
4. «Нет ни у кого» проверяется по открытым лентам конкурентов и выдаче Google News. Закрытые чаты радар не видит.
5. Сайты меняют адреса лент. Раз в неделю запускайте `check` и удаляйте из `config.yaml` то, что отдаёт ноль.
